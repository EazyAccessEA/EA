## Blockers

**L1. The domain doesn't serve anything yet.** `https://eazyaccess.org` returns a "Microsoft Azure Web App - Error 404"
page; `www` returns 530 (Cloudflare 1016, origin gone). Today, anyone typing the address sees an error.
Fix: the cutover below — with your OK.

**L2. Turnstile must list eazyaccess.org before the switch.** `siteverify` doesn't check the hostname, so the widget's
hostname list is the only gate; if eazyaccess.org isn't on it, every visitor gets "Spam check failed".
*You:* Cloudflare dashboard → Turnstile → the widget → Hostnames → add `eazyaccess.org` (covers www).
(Adobe Fonts needs nothing: the kit serves any domain — tested.)

**L3. No security headers.** No HSTS, CSP, `X-Content-Type-Options`, Referrer-Policy or frame protection on any
response (the contact form can be framed); plain HTTP isn't redirected. Observatory C.
Fix: `public/_headers` with HSTS, nosniff, `Referrer-Policy: strict-origin-when-cross-origin`, a CSP allowing self,
use.typekit.net, p.typekit.net and challenges.cloudflare.com with `frame-ancestors 'none'`; hashes for the two inline
scripts (build.mjs can compute them) rather than `'unsafe-inline'`; confirm the headers also reach `/` and `/contact`
(Worker-first routes) or set them in `worker.js`. Turn on *Always Use HTTPS* for the zone.

**L4. If the form breaks, nobody finds out.** `turnstileOk` (contact.js:32–45) returns `false` with no log when the secret
is missing or siteverify fails; Resend failures only reach `console.error`. The form is the studio's only lead channel.
Fix: log the Turnstile cause, and send a code-only alert (ntfy or Telegram URL in a secret) from both failure paths —
never the enquiry's content. *(Skeptic, confirmed in code.)*

**L5. The success message can say something untrue.** contact.js:131 and :151 return `{ok:true}` when the auto-reply was
rate-limited or failed, and main.js:232 always says "We've also emailed you to confirm it arrived".
Fix: return `confirmed: true/false` and show that sentence only when it's true; add a test per path.

**L6. Accessible names don't contain the visible text.** The six /work "Read the project" links are named
"Read the Farm Companion project" etc., which fails WCAG 2.5.3 (label in name). *(squirrelscan error; introduced today.)*
Fix: `aria-label="Read the project: Farm Companion"`.

**L7. No sitemap.** `/sitemap.xml` is 404. Fix: have `build.mjs` write it from its route list (the 404 page excluded),
and add a `Sitemap:` line via a custom `public/robots.txt`.

**L8. Companies House accounts are due on 30 November 2026** (13 days). The site prints the company number; from
1 December a prospect who looks it up sees "overdue", and late-filing penalties start. *You:* file the accounts to
28 Feb 2026. *(Skeptic; confirmed on Companies House.)*

## Should fix

- **S1. No DMARC record.** `_dmarc.eazyaccess.org` is empty, so `enquiries@`/`info@` can be spoofed and filters trust the
  domain less. Add TXT `v=DMARC1; p=none; rua=mailto:info@eazyaccess.org` (DNS; doesn't touch MX). With your OK.
- **S2. The auto-reply can be abused.** Each enquiry costs two Resend sends; the per-recipient limit is keyed on the raw
  address, so `name+1@gmail.com` variants each get their own bucket; bots that pass Turnstile could use up the free
  quota and push bounces. Fix: normalise the key and add a global cap — or drop the auto-reply (the page already confirms).
- **S3. Without JavaScript the form fails with no message.** No token → 403 → back to a blank form. Add a `<noscript>`
  line pointing to the email address.
- **S4. Emails take their links from whoever served the form.** `origin = new URL(request.url).origin` (contact.js:107):
  a submission via workers.dev puts workers.dev in both emails. Hard-code `https://eazyaccess.org`; set
  `workers_dev: false` once the domain works, so the duplicate copy stops being indexable.
- **S5. Social sharing and icons.** No `og:image` on any page (shares show no picture); `/favicon.ico` is 404.
- **S6. Privacy notice accuracy.** Say that Adobe counts page views for font licensing; that Resend keeps a copy of sent
  emails for its retention period and hosting logs keep IP addresses briefly; and word the processor sentence so Adobe
  isn't claimed to be under our data processing agreement.
- **S7. Desktop screenshot lazy-loaded above the fold** on project pages (squirrelscan lcp-hints): serve a tiny
  placeholder to phones with `<picture>`/`media` and load it eagerly on desktop.
- **S8. Turnstile result isn't tied to this site.** Check `j.hostname` (and an `action`) in `turnstileOk`.

## Cutover plan (Operator; check against your zone before acting)

0. Export the zone (DNS → Records → Export) — the rollback record.
1. Turnstile: add `eazyaccess.org` (L2).
2. Remove any Page/Redirect/Origin rules aimed at the dead Azure origin.
3. Delete **only** the apex and www A/AAAA records (and the `asuid` TXT). Never touch MX, SPF TXT, `google._domainkey`,
   `resend._domainkey`, `send`.
4. Add to `wrangler.jsonc` and deploy: `"routes": [{ "pattern": "eazyaccess.org", "custom_domain": true },
   { "pattern": "www.eazyaccess.org", "custom_domain": true }]`. Certificates take a minute or two.
5. Single Redirect rule: www → `https://eazyaccess.org` + path, 301. Turn on Always Use HTTPS.
6. Within 15 minutes: `dig +short eazyaccess.org MX` (5 Google hosts), SPF and both DKIM unchanged; `/` and `/contact`
   return 200 over HTTPS; www redirects; one real enquiry from a phone arrives in info@ with the auto-reply, both with
   `dkim=pass`; an outside email to info@ arrives.
7. Then set `workers_dev: false`, redeploy, and remove the workers.dev hostname from Turnstile.

Rollback: remove `routes`, redeploy, restore the apex/www records from the export (the old site was already a 404, so in
practice workers.dev stays up until step 7).
